# The Go port

The durin CLI was rewritten from TypeScript (Node 24) to Go. Commit `3ab3415` is the last one
that contains the TypeScript sources (`src/`) and the pnpm toolchain; check it out to see or
run the original.

## What stayed the same

- **Command-line surface**: commands, flags, help text, stdout/stderr bytes and exit codes.
  `internal/app/cli_options.go` reproduces Node's `parseArgs`, and every JSON the CLI prints
  goes through `internal/jsjson`, which matches `JSON.stringify` (key order, number and string
  formatting) and the terminal escaping in `terminalJson`.
- **State on disk and in the OS credential store**: profile files and their ids, the active
  profile, locks, revocation markers and pending-revocation index, the bridge's call ledger,
  hook installation records, agent configuration edits (`internal/jsonc` is a byte-exact port
  of jsonc-parser; `internal/toml` matches smol-toml), installed skills, and keyring entries
  (`internal/credentials` reads and writes exactly the entries `@napi-rs/keyring` 2.1.0 did on
  Linux, macOS and Windows).
- **Server contracts**: requests to the durin app, WorkOS and MCP gateways, OAuth discovery,
  dynamic client registration, PKCE, token, refresh and revocation requests
  (`internal/mcp` ports the subset of the TypeScript MCP SDK the CLI used, including how it
  reorders, strips and defaults JSON-RPC messages and tool results). Contract validation in
  `internal/contracts` follows the original zod schemas (`internal/zod`).
- **Ports**: `internal/ports` declares the same boundaries as `src/ports` as Go interfaces.

## What changed on purpose

- **Runtime**: setup copies the `durin` executable into `<config>/runtime/<sha256>/` and
  publishes `<config>/runtime/durin` (`durin.exe` on Windows). Agent configurations and hooks
  run that executable directly instead of `node <config>/runtime/cli.mjs`.
- **Migration**: running `durin` again replaces a bridge entry or hook the TypeScript CLI wrote
  (same profile and configuration directory, old Node launcher) with the new command, keeping
  comments and unrelated settings. Any other difference is still reported as a conflict.
  Until then, existing entries keep using the old runtime, which needs Node.
- **Bridge verification on Linux**: setup now passes `DBUS_SESSION_BUS_ADDRESS` and
  `XDG_RUNTIME_DIR` to the bridge it starts, so the bridge can reach the Secret Service. Before,
  setup failed at "Verify the saved agent bridge" on Linux. (Fixed in TypeScript first, in
  `137d583`.) It also passes `SSL_CERT_FILE` and `SSL_CERT_DIR`, Go's equivalents of
  `NODE_EXTRA_CA_CERTS`.
- **Interactive prompts** use Bubble Tea/huh instead of @clack/prompts. Questions, options,
  hints and messages are the same text; the drawing differs.
- **Telemetry** uses sentry-go with the same opt-outs (`DO_NOT_TRACK`, `NODE_ENV=test`) and the
  same scrubbing. CPU profiling is not available in Go and was dropped.
- **Distribution**: native executables. npm's `@accessdurin/cli` is now a small launcher that
  runs the executable from a per-platform package (`@accessdurin/cli-<os>-<arch>`), so
  `npx @accessdurin/cli` keeps working. See [distribution](distribution.md).

## How parity is checked

- `e2e/` runs a `durin` build against fake durin, WorkOS, OAuth and MCP servers with a real
  keyring and a pseudo-terminal, and compares each scenario's transcript (output, exit codes,
  files, keyring entries, HTTP requests) with goldens recorded from the TypeScript CLI (the
  sources at `3ab3415`). Run it with `e2e/run.sh`.
- Library packages carry differential fixtures generated by running the original JavaScript
  (Node's `URL`, `JSON`, jsonc-parser, smol-toml, zod, the MCP SDK, `@napi-rs/keyring` and the
  CLI's own TypeScript). Their generators live in each package's `testdata/` and import the
  pinned npm packages and `src/` from a checkout of `3ab3415` with `pnpm install` done; the
  committed fixtures are what `go test` uses, so Node is not needed to run the tests.
- To re-record goldens against the TypeScript CLI: in a `3ab3415` checkout run
  `pnpm install --frozen-lockfile && pnpm build`, then from this repository run
  `DURIN_BIN="node /path/to/that/checkout/dist/cli.js" DURIN_UPDATE_GOLDEN=1 e2e/run.sh`.
  A golden that changes for a new feature can be recorded from the Go build instead; review
  the diff either way.
